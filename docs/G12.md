# Conversation history

`getConversation(id)` in [the server-only getter](../lib/server/conversations/getter.ts)
loads conversation metadata and reads the transcript from LangGraph's latest
checkpoint snapshot. Server Components establish a request-time boundary, such as
`await connection()` from `next/server`, before calling the getter. Turn
reconciliation can call it directly. Each call reads current storage state.

On success the getter returns `conversation`, `messages`, and `pendingTurn`.
Messages use AI SDK `UIMessage` with the stored IDs and ordered text parts.
Provider reasoning and metadata stay in the checkpoint. A saved user message
followed by scheduled graph work yields the original user ID and its derived
assistant ID. When no turn is pending, `pendingTurn` is `null`. The getter
doesn't consume the live stream, so provisional text stays out of history.

| Case | Result |
| ---- | ------ |
| Existing conversation with no checkpoint | Metadata, `messages: []`, `pendingTurn: null` |
| Malformed UUID | `ChatError` with code `validation` |
| Valid UUID with no metadata row | `ChatError` with code `missing-conversation` |
| Failed metadata or checkpoint read | `ChatError` with code `database` |

## Human verification

Use the configured local database and import `getConversation` in the same
server-side TypeScript context used for [G11 verification](G11.md#manual-verification).

1. Read a newly created conversation and confirm its metadata, empty messages,
   and `pendingTurn: null`.
2. Read the conversation used for G11. Compare the displayed text and message
   IDs with `snapshot.values.messages` from G11. Confirm `pendingTurn: null`
   after a completed turn.
3. Read a malformed ID and a valid UUID absent from the database. Confirm the
   `validation` and `missing-conversation` results respectively.
4. If a conversation has a checkpointed user message awaiting model execution,
   confirm `pendingTurn` contains that user ID and the matching assistant ID.
   Confirm that any provisional assistant text from the interrupted attempt is
   absent from `messages`.
