# G10 - Conversation collection API

`GET /api/conversations` and `POST /api/conversations` use the server-only
metadata repository in [metadata.ts](../lib/server/conversations/metadata.ts).
Database initialization remains lazy and uses only the runtime database client.

| Request | Success response |
| --- | --- |
| GET | HTTP 200 with `{ conversations: ConversationMetadata[] }`; an empty collection returns `{ conversations: [] }`. |
| POST | HTTP 201 with a single `ConversationMetadata` object. No request body is required. |

Creation inserts the fixed title `New chat` and lets the existing PostgreSQL
defaults generate the UUID and `createdAt`. It leaves `updatedAt` null.
Both operations serialize database dates into ISO strings and validate metadata
with the shared schema. Listing orders by
`coalesce(updated_at, created_at) DESC, id DESC`, matching the existing activity
index and giving ties a deterministic order.

The GET handler awaits `connection()` before entering its error handler or
initializing the database. This keeps reads at request time and lets Next.js
defer prerendering without swallowing its control flow. POST handlers already
execute at request time. Neither handler caches data; all responses carry
`Cache-Control: no-store`. Cache Components stays enabled and the route adds no
unsupported segment configuration exports.

Storage failures return HTTP 503 with the shared, fixed `database` error.
Driver exceptions, SQL, configuration values, and validation details are not
included in the response. These operations access only conversation metadata;
they do not initialize checkpoint storage or invoke a model.

## Human verification

With the existing database and runtime configuration ready, start the app with
`npm.cmd run dev`. In another PowerShell window, use:

```powershell
curl.exe -i http://localhost:3000/api/conversations
curl.exe -i -X POST http://localhost:3000/api/conversations
curl.exe -i http://localhost:3000/api/conversations
```

Confirm POST returns HTTP 201, a UUID, the title `New chat`, an ISO creation
timestamp, and `updatedAt: null`. Confirm the subsequent GET includes the same
metadata. Create another conversation and confirm descending activity ordering.
For conversations with equal activity timestamps, UUIDs sort descending.
An already-empty database should return an empty array; do not delete existing
data just to check this case.

Inspect both success and failure responses for `Cache-Control: no-store`.
If storage is unavailable, confirm the response is HTTP 503 with
`{ error: { code: "database", message: "Conversation storage is unavailable. Please try again." } }`.
The agent does not execute these requests, change the database schema, or run
automated tests.
